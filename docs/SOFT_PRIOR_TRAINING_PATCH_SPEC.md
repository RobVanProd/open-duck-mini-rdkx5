# Soft-Prior Training Patch Spec

Date: 2026-06-25

This spec defines the next offline code change needed in the sibling
`Open_Duck_Playground` checkout. It does not authorize training, robot tests,
SSH, deploy, or runtime behavior changes.

## Why This Patch Exists

The compact soft-prior config is ready:

```text
outputs/analysis/soft_prior_fragment_config.json
status: PASS_SOFT_PRIOR_CONFIG_READY
```

The prior-only replay holds:

```text
1.2 s: HOLD_SOFT_PRIOR_LATERAL_UNSTABLE
3.0 s: HOLD_SOFT_PRIOR_FREEZE
```

So the prior is useful motion-shape material, but not a controller or hard
label. The next valid experiment is a learner that treats the prior as a weak,
default-off auxiliary cost while the real task reward still demands forward
motion, posture, and survival.

### Config

Add:

```text
soft_prior.enable = False
soft_prior.action_mean = []
soft_prior.joint_indices = [2, 3, 4, 11, 12, 13]
soft_prior.period = 50
soft_prior.scale = 0.0
soft_prior.huber_delta = 0.05
soft_prior.phase_source = imitation_i or step
```

Add reward scale:

```text
reward_config.scales.soft_prior = 0.0
```

### Runner CLI

Add flags:

```text
--enable_soft_prior
--soft_prior_config_json PATH
--soft_prior_scale FLOAT
--soft_prior_huber_delta FLOAT
--soft_prior_phase_source imitation_i|step
```

Loading `--soft_prior_config_json` should read the compact config generated by:

```text
tools/build_soft_prior_fragment_config.py
```

Do not read raw trace JSONL files during training.

### Reward Term

Add one auxiliary cost:

```text
soft_prior_action = action_mean[phase_index]
cost = mean(pseudo_huber(action[joint_indices] - soft_prior_action, huber_delta))
```

Only pitch-chain joints should be included initially:

```text
left_hip_pitch
left_knee
left_ankle
right_hip_pitch
right_knee
right_ankle
```

Do not force yaw/roll/head actions from the fragment.

### Metrics

Record:

```text
cost/soft_prior
diagnostic/soft_prior_phase
diagnostic/soft_prior_cost
```

The candidate gate should report these terms in the same reward-term table as
the existing progress, pitch, action-rate, and target-rate terms.

## First Training Recipe

Only after the patch imports and the config loads:

```text
recipe: movement_bootstrap_v21_soft_prior_x004
phase count: 1
command_x: 0.04 only
bridge: off
zero_command_probability: 0.0
soft_prior_scale: small negative cost, scheduled down if possible
forward progress floor: active
wrong-direction penalty: active
overshoot penalty: active
pitch / pitch-rate / base-height terms: active
alive dominance: low
```

Do not add fitted bridge until the vanilla low-command gate passes.

## Gate

Grade by multi-seed rollout, not training reward:

```text
seeds: 0-7
mean local vx > 0.02 m/s
track ratio positive and below 2.0
no reverse seed
standstill seeds reduced from V10/V18/V20 baselines
falls reduced or delayed without freezing
target velocity remains inside envelope
```

Pass:

```text
PASS_SOFT_PRIOR_LEARNER_X004
```

Hold:

```text
HOLD_SOFT_PRIOR_LEARNER_FREEZE
HOLD_SOFT_PRIOR_LEARNER_REVERSE
HOLD_SOFT_PRIOR_LEARNER_LUNGE
HOLD_SOFT_PRIOR_LEARNER_COLLAPSE
HOLD_SOFT_PRIOR_LEARNER_ABOVE_ENVELOPE
```

## Stop Rule

If the first soft-prior learner freezes, reverses, or collapses across the
same seed distribution, do not keep increasing `soft_prior_scale`.

Next branch would be:

```text
new generator structure, or external/reference gait with compatible contact and
target-rate behavior
```

## Non-Goals

```text
do not run robot validation
do not run x=0.08
do not deploy
do not relax actuator envelope
do not train against raw trace labels
do not use the compact prior as a hard controller
```
